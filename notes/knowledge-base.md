## 三、Day 1 · 2026-10-30 · C 语言从零到素数

| 编号 | 知识点 | 要点 | 易错点 / 安全关联 | 掌握度 |
|---|---|---|---|---|
| C01 | 源文件 → 可执行文件 | `.c` 是给人看的文本，`.exe` 是给机器执行的二进制，中间靠编译器翻译 | 以为改完源码程序就自动变了，忘了重新编译 | ⭐⭐ |
| C02 | `#include <stdio.h>` | 把头文件的内容"复制粘贴"进来，主要是为了拿到 `printf` 的声明 | 写成 `"stdio.h"` 也能过，但引号是"先找当前目录"，尖括号才是标准库 | ⭐⭐ |
| C03 | `int main(void)` | 程序入口；`return 0` 把 0 交给操作系统表示"正常结束" | 写成 `main(vido)` 这种拼写错误，编译器报的错常指错行 | ⭐⭐ |
| C04 | `printf` 与 `%d`、`\n` | `%d` 是占位符，`\n` 是换行符 | 用中文引号 `"` `"` 编译不过 | ⭐⭐ |
| C05 | `%` 取余 | `i % m == 0` 表示 i 能被 m 整除 | 和 `/` 搞混：`7 / 2` 是 3（整除），`7 % 2` 是 1 | ⭐⭐ |
| C06 | `=` 与 `==` | `=` 是赋值（把右边塞进左边），`==` 是比较（问两边相等吗） | `if (x = 5)` 语法合法但永远为真，是经典 bug；也是"表达式必须是可修改的左值"报错来源 | ⭐⭐ |
| C07 | `for (初始化; 条件; 步进)` | 三段用分号隔开，缺一不可（缺初始化段会直接编译报错） | `m<=i-1;m++` 忘了写 `m = 2` 这一段 | ⭐⭐ |
| C08 | `break` | 立刻跳出整个循环 | 写在 `if` 外面就变成"第一轮就退出" | ⭐⭐ |
| C09 | `flag` 标志变量 | 先假设是素数（`flag = 1`），发现能整除就改成 0 | 最后 `return flag` 时把 flag 反过来理解，导致 7 被判断成"不是素数" | ⭐⭐ |
| C10 | 素数定义 | 只能被 1 和它自己整除、且**大于 1** 的整数 | 边界：**1 不是素数**；`is_prime(1)` 按朴素写法会错误返回真 | ⭐⭐ |
| C11 | 试除范围优化 | `n-1` → `n/2` → `√n`（写成 `m*m <= n`）。因为因子成对出现，小的那个一定 ≤ √n | 以为 `n/2` 是"一半"，其实是因为 m > n/2 时乘 1 小于 n、乘 2 大于 n | ⭐⭐ |
| C12 | 变量声明 vs 赋值 | `int a = 1;` 是**两件事**：在栈上开 4 字节 + 把 1 写进去 | 停在这一行时两件事都还没做，此时读 a 读到的是垃圾值 | ⭐⭐ |

## 四、Day 2 · 2026-10-31 · 函数化与 Git

| 编号 | 知识点 | 要点 | 易错点 / 安全关联 | 掌握度 |
|---|---|---|---|---|
| C13 | 函数是什么 | 一段有名字、有输入、有输出的代码。**拆出来的目的是"一处修改，处处生效"** | 以为函数只能"少写几行代码"——真正价值是可复用、可测试、可替换 | ⭐⭐ |
| C14 | 函数四要素 | 返回类型 / 函数名 / 参数列表 / 函数体 | `int is_prime(int n)` 里第一个 `int` 是**返回什么**，括号里的是**要什么** | ⭐⭐ |
| C15 | `return` | 立即结束函数并把值交回去 | 函数声明是 `int` 就必须返回 `int`，否则返回值不确定 | ⭐⭐ |
| C16 | 职责分离 | `is_prime` 只负责"判断"，`main` 只负责"打印"。函数不打印任何东西 | 在 `is_prime` 里写 `printf`，函数就没法在别处复用了 | ⭐⭐ |
| C17 | 命名要表意 | `osm` → `is_prime`。读代码的人看到名字就该知道它干什么 | 单字母 / 拼音缩写命名，一周后自己都看不懂 | ⭐⭐ |
| C18 | 调用即求值 | 写 `is_prime(7)` 就是在问"7 是素数吗"，答案就是 `return` 回来的那个值 | 以为写了函数它就会自动执行——**函数不调用就不跑** | ⭐⭐ |
| C19 | Git 三个区 | 工作区（你改的文件）→ 暂存区（`git add` 后）→ 仓库（`git commit` 后） | 直接 `git commit` 不 `git add`，报 "nothing added to commit" | ⭐ |
| C20 | `git add` / `commit` / `push` | add 挑货、commit 打包封箱、push 发货到 GitHub | 以为 commit 就上传了——commit 只到本地 | ⭐ |
| C21 | commit 与 push 的区别 | **commit 存本地硬盘，push 才是上传副本** | push 失败 ≠ 作业丢了 | ⭐ |
| C22 | `.gitignore` | 告诉 Git 哪些文件不追踪（编译产物 `.exe`、`.obj`、`.vs/`） | 把 `x64/` 编译产物提交上去，仓库体积爆炸 | ⭐ |
| C23 | `git add .` 的坑 | `.` 会把当前目录**所有**变动一次性暂存，包括你不想提交的 | 实际发生过：空文件 `notes/day02.md` 被顺手带进 perf 提交。老手用 `git add -p` 逐块确认 | ⭐ |
| C24 | 提交身份 name/email | 每次 commit 都记录"谁提交的"，没配置就报 `Author identity unknown` | **Windows 的 git 和 WSL 的 git 是两套独立配置，不共享** | ⭐ |
| C25 | noreply 马甲邮箱 | `331912106+liang265@users.noreply.github.com` | 用真实邮箱提交会被 GitHub 拒绝推送（「阻止暴露我邮箱」开关）；**邮箱泄露 = 被社工的入口** | ⭐ |
| C26 | commit ID | 一串哈希（如 `310e285`），内容变则哈希变 | 以为改了内容哈希不变——这正是 Git 防篡改的原理 | ⭐ |

## 五、Day 3 · 2026-11-03 · Linux、权限、编译器、调试器

| 编号 | 知识点 | 要点 | 易错点 / 安全关联 | 掌握度 |
|---|---|---|---|---|
| L01 | `pwd` | print working directory，我在哪 | — | ⭐⭐ |
| L02 | `cd` | change directory。`cd ~` 回家，`cd ..` 上一层，`cd -` 回上次的地方 | 路径打错不报错、只是没动（cd 到不存在目录才报错） | ⭐⭐ |
| L03 | `ls -l` 七列 | 权限 / 硬链接数 / 所有者 / 所属组 / 大小 / 修改时间 / 文件名 | `-l` = long；另有 `-a` 显示隐藏文件、`-h` 人类可读、`-t` 按时间、`-r` 反序 | ⭐⭐ |
| L04 | `mkdir -p` | `-p` = parents，父目录不存在就一起建，已存在也不报错 | 忘 `-p` 时 `mkdir ~/a/b/c` 直接失败 | ⭐⭐ |
| L05 | `cp` / `mv` / `rm` | 复制 / 移动兼改名 / 删除 | **`rm` 没有回收站**，删了就没了；`rm -rf` 尤其危险 | ⭐⭐ |
| L06 | `cat` / `head` / `tail` / `wc` | 全看 / 看前几行 / 看后几行 / 数行数字数 | `wc -l` 数行 | ⭐⭐ |
| L07 | `grep` | 在文本里找匹配的行 | 和 `find` 分工：**grep 找内容，find 找文件名** | ⭐⭐ |
| L08 | `find ~ -name "*.c"` | 按名字找文件 | `-name"*.c"` 少个空格 → `find: unknown predicate` | ⭐⭐ |
| L09 | **空格是分隔符** | 命令、选项、参数之间**必须**有空格 | 你一天栽了两次：`cp xxx.c.` 和 `-name"*.c"` | ⭐⭐ |
| L10 | Tab 补全 | 敲前几个字母按 Tab，自动补全路径/文件名 | 不确认文件名就硬猜，是"命令找不到文件"的头号原因 | ⭐⭐ |
| L11 | 权限 r/w/x = 4/2/1 | `rwx` = 7，`r-x` = 5，`rw-` = 6；`644` = `rw-r--r--` | 认为权限是三个独立开关，其实是二进制位 | ⭐⭐ |
| L12 | `chmod` | `chmod 644 file` 改权限；`+x` 加执行权 | 给源码 `777` 完全没必要 | ⭐⭐ |
| L13 | **最小权限原则** | 只给"够用"的权限，多一点都不给 | 源码不需要 `x`；数据库账号不该有 DROP 权；这是整个安全学科的底层思想 | ⭐⭐ |
| L14 | NTFS 挂载显示 777 | `/mnt/d` 下的文件，Linux 看到的是统一 777，因为 NTFS 根本没有 Linux 权限概念 | 以为这是"我的文件权限错了" | ⭐⭐ |
| L15 | `umask` | 新建文件的"默认扣掉的权限"，WSL 里是 `0022` | 所以 `cp` 一个 777 文件过来会变成 755 | ⭐⭐ |
| L16 | `ps aux` / `top` | 看进程列表；`top` 按 `q` 退出 | 用 `top` 之后不知道怎么退出 | ⭐ |
| L17 | 管道 `\|` | 左命令的输出，直接当右命令的输入 | 以为管道是"两个命令同时跑" | ⭐⭐ |
| L18 | 重定向 `>` `>>` | `>` 覆盖写进文件，`>>` 追加 | 不小心 `>` 把重要文件清空 | ⭐⭐ |
| L19 | 文件描述符 0/1/2 | 0=标准输入、1=标准输出、2=标准错误 | 不知道 `2>` 是"只重定向错误"，以为和 `>` 一样 | ⭐⭐ |
| L20 | `/dev/null` | "黑洞"设备，写进去的东西直接丢弃 | — | ⭐⭐ |
| L21 | **SUID** | 文件有 SUID 位时，任何人执行它都**临时获得文件所有者的权限** | `ls -l /usr/bin/passwd` 里的 `s`（`-rwsr-xr-x`）就是它；**SUID 程序是提权漏洞的头号目标** | ⭐⭐ |
| L22 | 4 位权限 | 4=SUID、2=SGID、1=Sticky | `chmod 4755` 就是加 SUID | ⭐⭐ |
| L23 | `find / -perm -4000 -type f 2>/dev/null` | 找所有带 SUID 的可执行文件 | `-perm -4000`（包含）vs `-perm 4000`（恰好）；`-xdev` 不跨文件系统，否则爬进 `/mnt/d` 卡死 | ⭐⭐⭐ |
| L24 | `find /` 会爬进 Windows | 因为 `/mnt/c`、`/mnt/d` 挂着整个 Windows 盘 | 卡住十分钟不知道怎么停 → `Ctrl+C` | ⭐⭐ |
| L25 | `hash -r` | 清空 bash 的"命令路径缓存" | 明明装了 `gdb` 却报 `command not found` | ⭐ |
| L26 | command not found 四步排查 | `which` → 用绝对路径 → `hash -r` → `echo $PATH` | — | ⭐ |
| L27 | `gcc` 是什么 | GNU Compiler Collection，GNU 工程的 C 编译器；GNU 1983 由 Richard Stallman 发起，GPL 协议要求"改了必须开源" | 以为 gcc 只编 C（其实 g++/gcc 都归 GCC 管） | ⭐⭐ |
| L28 | 编译四个阶段 | 预处理 `-E` → 编译 `-S` → 汇编 `-c` → 链接 | 以为"编译"是一个动作 | ⭐⭐ |
| L29 | `gcc -g -O0 -Wall -o toy toy.c` | `-g` 加调试信息、`-O0` 不优化、`-Wall` 开全部警告、`-o` 指定输出名 | **不加 `-g` 就没法用 gdb 看变量和行号** | ⭐⭐⭐ |
| L30 | MSVC 与 gcc 的写法差异 | MSVC 用斜杠 `/Zi /Od /W3`，gcc 用横线 `-g -O0 -Wall`；这是 DOS 与 Unix 的历史差异 | — | ⭐ |
| L31 | gdb 基本操作 | `list` 看源码、`break 名字` 下断点、`run` 跑起来、`next` 单步、`print x` 看变量、`quit` 退出 | `list` 是 gdb 内命令，在 shell 里敲会 `command not found` | ⭐⭐ |
| L32 | 断点地址 `0x1174` | 断点落在某个内存地址上；`line 4` 告诉你在源码第 4 行 | — | ⭐ |
| L33 | **未初始化内存** | C 不会自动清零局部变量。赋值前读它，读到的是**上一任留下的残留**（garbage value） | `print a` 得到 `32767`，`next` 之后才变成 `1` | ⭐⭐⭐ |
| L34 | 未初始化 = 未定义行为 | C 标准明确规定读未初始化变量是未定义行为，编译器可以做任何事 | 以为"应该是 0" | ⭐⭐⭐ |
| L35 | `32767` = `0x7FFF` | 64 位栈地址的高 32 位（如 `0x00007ffd...`）；ASLR 只随机低 32 位，**高 32 位恒定** | **可预测 = 可利用**；这是地址泄露能绕过 ASLR 的原因 | ⭐⭐ |
| L36 | **Heartbleed CVE-2014-0160** | OpenSSL 信了攻击者伪造的长度字段，把内存里 65534 字节原样返回，泄露密码、会话密钥、服务器私钥 | 全球约 17% 的 HTTPS 服务器受影响；**未初始化内存 → 信息泄露 → 现实灾难**的教科书案例 | ⭐⭐ |

## 九、Day 4 · 2026-11-04 · 权限复核 + gdb 流程控制 + ASLR 实测

| 编号 | 知识点 | 要点 | 易错点 / 安全关联 | 掌握度 |
|---|---|---|---|---|
| G01 | 10 个字符 = 1+3+3+3 | 第 1 位是类型（`-` 文件 / `d` 目录 / `l` 链接），后面三组依次是**所有者 / 同组 / 其他人**的 `rwx` | 只记得"有三个 rwx"，说不出分别是谁的 | ⭐⭐ |
| G02 | `chmod 000` 锁死自己 | 权限对**文件主人也生效**，没有"我是主人所以网开一面" | `cat` 报 `Permission denied`——这是内核真的在拒绝 | ⭐⭐ |
| G03 | `continue` / `c` | 放行，跑到下一个断点或程序结束 | 和 `next` 混：`next` 走一行，`c` 走到底 | ⭐⭐ |
| G04 | `bt` 调用栈 | 列出"我是被谁调用的"；`#0` 是当前，`#1` 是上层 | 崩溃现场第一件事就是 `bt`，没有它只能盯一堆地址 | ⭐⭐ |
| G05 | `frame N` / `f N` | 在栈帧之间上下楼，`f 1` 回到调用者那一行 | 以为 `f` 是"fight"或别的什么 | ⭐⭐ |
| G06 | 逃生三连 `kill`/`delete`/`quit` | 程序"卡死"多半是停在你不知道的断点上，`kill` 一下立刻解脱 | `run` 问 `Start it from the beginning?` 答 `n` 会导致什么也没发生 | ⭐⭐ |
| G07 | `next` vs `step` | `next` 把函数整个跑完；`step` 钻进函数第一行 | 新手一直按 `next`，bug 就藏在被跳过的函数里 | ⭐⭐ |
| G08 | `set disable-randomization off` | gdb **默认关掉 ASLR** 让调试可复现 | 不关掉，你看到的是"实验室里的世界"，不是攻击者面对的战场 | ⭐⭐ |
| G09 | ASLR 页对齐 | 地址 = 页基址（随机）+ 页内偏移（不变）；一页 4096 字节 = `0x1000`，所以低 3 位十六进制恒定 | 实测三次：`...41cd` / `...e1cd` / `...c1cd`，尾巴 `1cd` 从不改变 | ⭐⭐ |
| G10 | `set` 报 `No symbol` | `set xxx` 里 `xxx` 被当成设置项名，打错就说"没有这个符号" | 打成了 `disable_randomization`（下划线），正确是 `disable-randomization`（连字符） | ⭐⭐ |
| G11 | git 不读注册表代理 | Windows 的「Internet 选项」代理只对 WinINET 程序有效；**git 用 libcurl，必须另配** `git config --global http.proxy http://127.0.0.1:端口` | 现象极具迷惑性：浏览器能开 GitHub，`Test-NetConnection` 也通，但 `git push` 报 443 超时 | ⭐ |
| G12 | `mv` 改名 / `git mv` | `mv 旧名 新名` 在同一目录里就是改名；文件已提交过则用 `git mv` 保留历史 | 文件名 `dayo4.md`（字母 o）应为 `day04.md`（数字 0）——同形字第三次出现 | ⭐⭐ |
| G13 | `rm -rf` 铁律 | 先 `ls -R` 看内容，再 `pwd` 确认位置，最后才删 | `-r` 递归 + `-f` 强制不询问，敲错一个空格能删掉整个目录 | ⭐⭐ |
